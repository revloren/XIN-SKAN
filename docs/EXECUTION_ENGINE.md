# Execution Engine

Execution Engine отвечает на вопрос «что запускалось»: какие программы, когда и сколько раз, какие файлы они при этом открывали. History Engine показывает, что файл *был*; Execution Engine — что его *запускали*. Тип события `Executed` разрешён только этим источникам: файловая система, MFT, USN и Корзина запуск показать не могут, и схема свидетельств это запрещает.

**Ни одна запись Execution Engine не является выводом о нарушении.** Запуск — факт уровня Informational. Low получают только косвенные признаки сокрытия (выключенный Prefetch, отключённая служба SysMain), и в обосновании перечислены их безобидные причины. Названия чит-клиентов здесь не распознаются: это задача проверенной базы (этап 9).

| Модуль | Источник | Нужны права | Что записывает |
| --- | --- | --- | --- |
| `prefetch` | `C:\Windows\Prefetch\*.pf` (версии 17, 23, 26, 30, 31; сжатые MAM) | администратор | запуск программы: путь, число запусков, до 8 последних времён; JAR-файлы, которые программа открыла в первые секунды |
| `bam` | `HKLM\SYSTEM\CurrentControlSet\Services\bam` и `dam` | администратор | запуск программы пользователем: путь, SID и имя профиля, время последнего запуска |
| `amcache` | `C:\Windows\AppCompat\Programs\Amcache.hve` с журналами `.LOG1`/`.LOG2` | администратор (чтение тома) | файл существовал и был учтён Windows: путь, SHA-1, размер, версия, издатель, программа |

## Prefetch

**Свой разбор.** Библиотека Prefetch в `LIBRARY_REVIEW.md` была кандидатом, но, как и для LNK и Jump Lists, написан собственный разбор: каждое смещение и длина проверяются по буферу, распаковка ограничена 64 МБ. Распаковка сжатых файлов Windows 10/11 — собственная реализация XPRESS Huffman по спецификации MS-XCA (без вызова `RtlDecompressBufferEx`, чтобы разбор работал одинаково на любой системе и в тестах).

Оракул — корпус и ожидаемые значения из тестов самой библиотеки (Windows XP, 2003, Vista, 7, 8, 2012, 2012 R2, 10):

- 54 файла корпуса читаются без единой проблемы; единственный «плохой» файл (`Bad/notAPrefetch.pf`) правильно не признан Prefetch;
- совпадают версия, хеш, число запусков, время последнего запуска, тома (путь устройства, серийный номер), число файлов и папок, ссылки MFT.

**Что записывается:**

- запуск Java (`java.exe`, `javaw.exe`) и известных лаунчеров Minecraft;
- запуск программ из папок Minecraft, загрузок и временных папок, из профиля пользователя, со съёмного диска и с тома, который сейчас не подключён (например, флешка);
- JAR-файлы, которые программа открыла в первые ~10 секунд запуска (для Java это игра и её моды). Собственные библиотеки игры (`.minecraft\libraries`) не записываются. Тип события — `Loaded`: Prefetch показывает, что файл открывался, а не то, что его запускали как программу.

Программы Windows из системных папок не записываются.

**Пути.** Prefetch хранит пути в виде `\VOLUME{время-серийный номер}\…` или `\Device\HarddiskVolumeN\…`. Модуль переводит их в букву диска по серийному номеру или имени устройства подключённых сейчас томов (`QueryDosDeviceW`, `GetVolumeInformationW`). Если том не подключён, путь остаётся как записан, запись получает статус Partial и ограничение `PATH.VOLUME_UNKNOWN`, а серийный номер тома — атрибут `Volume.Serial`, по которому её можно связать с ярлыком (этап 7).

**Время.** Последний запуск — основная метка; остальные до семи — дополнительные. Windows записывает время примерно через 10 секунд после старта программы, это указано как погрешность. Время создания и изменения самого `.pf` тоже записываются.

**Выключенный Prefetch.** Если `EnablePrefetcher` равен 0 или 2 (запуски программ не записываются) или служба SysMain отключена, записывается Low. Так скрывают следы запуска, но так же делают «оптимизаторы» и советы «ускорить SSD»; на серверных Windows сбор выключен по умолчанию.

**Ограничения:**

- до 1024 файлов (Windows 8+) или 128 (XP/7), и только 8 последних запусков на программу; файлы можно удалить;
- отсутствие файла ничего не доказывает;
- список файлов — только первые ~10 секунд работы программы: моды, загруженные позже, в нём могут отсутствовать.

## BAM

Background Activity Moderator (Windows 10 1709+) хранит для каждого пользователя по одной записи на программу: путь и время. Читаются `bam\State\UserSettings` (1809+) и `bam\UserSettings` (1709–1803), а также `dam`. Имя профиля для SID берётся из `ProfileList`.

- Записи текущего пользователя читаются всегда; других — только с разрешением на чужие профили, иначе покрытие Partial с `BAM.OTHER_USERS`.
- Отбор тот же, что у Prefetch; приложения Магазина (по имени пакета) не записываются.
- Время — последний раз, когда Windows обновила запись. По исследованиям это происходит при завершении программы, поэтому оно может быть позже запуска.

**Ограничения:** одна запись на программу; записи старше примерно недели Windows удаляет при загрузке; консольные и фоновые программы могут отсутствовать.

## Amcache

**Почему не «запуск».** С Windows 10 Amcache — инвентаризация: Windows записывает программы, которые видела при установке, запуске или проверке совместимости. Поэтому событие — `Existed`, а не `Executed`. Ценность записи — SHA-1: по нему файл можно узнать, даже если его удалили или переименовали (сопоставление с проверенной базой — этап 9).

**Чтение занятого файла.** Windows держит загруженный куст открытым монопольно, поэтому обычное открытие (даже с полным разделением) не проходит. Модуль сначала пробует его, а затем читает файл с тома: модуль MFT во время своего прохода запоминает записи `Amcache.hve`, `NTUSER.DAT`, `UsrClass.dat`, их журналов и `SRUDB.dat`, а модуль Amcache читает кластеры файла по его цепочке (с продолжениями из записей расширения). Ничего не копируется, служба теневых копий и API резервного копирования не используются, том открыт только на чтение. В атрибуте `Amcache.ReadMethod` указано, как прочитан файл. Если модуль MFT не выполнялся, Amcache сообщает, что файл занят, а не молчит.

**Свой разбор кустов реестра.** Формат regf 1.3–1.6: ключи, значения, списки подключей `lf`/`lh`/`li`/`ri`, большие значения `db`. Каждое смещение проверяется по размеру куста, списки проверяются на зацикливание.

**Журналы транзакций.** С Windows 8.1 куст на диске обновляется редко, а свежие изменения лежат в `.LOG1`/`.LOG2`. Если куст «грязный» (номера последовательности не совпадают), записи журналов (`HvLE`) применяются по порядку номеров, начиная с первой не старше куста. Каждая запись проверяется двумя хешами Marvin32; запись с неверным хешем, пропуск номера или остаток от прошлого использования файла журнала останавливают восстановление, и это записывается (`AMCACHE.DIRTY`, покрытие Partial). Журналы старого формата (до Windows 8.1) не применяются.

Оракул — образцы библиотеки AmcacheParser (DFIR Artifact Museum): «грязный» куст Windows 10 после применения 4 записей журналов (номера 36–39; остаток с номером 27 правильно не применён) содержит 124 файла, как в тестах библиотеки, а без журналов — 123; значения конкретной записи (SHA-1, размер, время ключа) совпадают. Старый формат (Windows Server 2012 R2) — 136 файлов. Кусты из тестов библиотеки Registry (SAM, DRIVERS с 3 878 подключами в списке `ri`) читаются без проблем.

**Что записывается:** файлы Java и лаунчеров, файлы в профилях пользователей (свой — всегда, чужие — с разрешением), во временных папках, в папках Minecraft, на съёмных дисках. Системные файлы Windows и Program Files не записываются (кроме Java).

**Ограничения:** SHA-1 Windows считает по первым 31,4 МБ файла; запись не доказывает запуск; на Windows 7 без обновлений Amcache нет.

## Аудит

Каждый открытый ключ `HKLM` записывается в журнал аудита (`read-registry`, доступ только на чтение). Папка Prefetch и файлы `.pf` открываются через тот же `IFileSource`, что и в остальных модулях (GENERIC_READ, полное разделение).

## Где проверено

| Что | Как |
| --- | --- |
| Разбор Prefetch | Синтетические файлы всех версий; корпус и значения тестов библиотеки (CI); 9 000 повреждённых копий (без исключений) |
| XPRESS Huffman | Тестовый кодировщик (все 512 символов по 9 бит), круговая проверка на 150 КБ (три блока); 2 000 повреждённых потоков — только `InvalidDataException` |
| Модули | Java с модом и игрой, программа из загрузок, программа с отключённого тома, системная программа (не записана), повреждённый файл; BAM: свой и чужой пользователь, съёмный диск, пакет Магазина |
| Кусты реестра | Синтетические кусты (все виды списков, кириллица, большие значения), «грязный» куст и журнал из двух записей, неверный хеш, журнал прошлого поколения; 3 000 повреждённых кустов; образцы AmcacheParser и Registry (CI) |
| Чтение занятого файла | Тестовый том NTFS: удалённый `injector.exe` (5000 байт в кластерах) прочитан по записи MFT; `$Boot` через запись совпадает с первым сектором; чужая запись распознана. CI: настоящий занятый `Amcache.hve` прочитан с системного тома |
| Живая система | CI: тома, реальный реестр и папка Prefetch; запуск программы из временной папки — видят ли её Prefetch и BAM — измеряется и печатается. Время последней записи ключей реестра до и после чтения совпадает. |
