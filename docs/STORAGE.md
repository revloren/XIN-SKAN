# Хранилище проверки

Каждая проверка — отдельная база SQLite `evidence.db` в собственной папке, созданной через `OutputSink`. Код: `src/XINSkan.Storage`.

## Принципы

- **Только добавление.** Триггеры прерывают любой `UPDATE` и `DELETE` в таблицах `Evidence`, `SourceCoverage`, `ModuleResults`, `ModuleErrors`, `Investigations`. Даже ошибка в коде XIN SKAN не может переписать собранное.
- **Фиксация после каждого модуля.** Записи буферизуются (по умолчанию 500) и пишутся транзакциями; `CheckpointAsync` записывает всё накопленное вместе с результатом модуля в одной транзакции. После фиксации записи модуля переживают отмену, сбой следующего модуля или аварийное завершение.
- **Ошибка записи не теряет данные молча.** Если транзакция не прошла (например, повтор `EvidenceId`), ничего частичного не фиксируется, записи остаются в буфере, а ошибка поднимается наверх: проверка не может утверждать, что сохранила то, чего не сохранила.
- **Все файлы на учёте.** База открывается в режиме журнала `PERSIST`; файл журнала `evidence.db-journal` заранее заявляется через `OutputSink`. SQLite не создаёт и не удаляет файлов в обход учёта, и манифест целостности перечисляет всё содержимое папки.
- **Чтение не меняет базу.** `InvestigationReader` открывает её в режиме только для чтения; тест сверяет хеш файла до и после чтения.
- **Резервная копия.** `BackupTo` пишет согласованную копию в новый файл папки проверки (без журнала).

## Таблицы

| Таблица | Содержание |
| --- | --- |
| `SchemaInfo` | Версия схемы (1) и время создания |
| `Investigations` | Заголовок проверки: ID, время начала, версия, оператор, компьютер, ОС, часовой пояс |
| `Evidence` | Свидетельства по схеме v1 (`docs/EVIDENCE_SCHEMA.md`); структурированные поля — JSON |
| `SourceCoverage` | Покрытие источников |
| `ModuleResults` | Результат каждого модуля: состояние, время, число записей, причина |
| `ModuleErrors` | Ошибки, не остановившие модуль |
| `FileEvents` (представление) | Свидетельства о файлах: Existed, Created, Modified, Renamed, Moved, Deleted, Accessed, Downloaded |
| `ExecutionEvents` (представление) | Свидетельства о запуске: Executed, ExecutedLikely, Loaded |

Таблицы ТЗ `NetworkEvents`, `NetworkConnections`, `NetworkApplications`, `TrafficStatistics`, `CheatSignatures`, `FeatureSignatures`, `HashSignatures`, `Applications`, `Correlations`, `Reports` появятся в миграциях соответствующих этапов. `AuditLog` хранится не в базе, а отдельным файлом с цепочкой хешей (`docs/SECURITY.md`), чтобы его целостность не зависела от базы.

## Индексы

Нормализованный путь, имя файла, пара (запись MFT, sequence), время события, модуль, SHA-256 объекта — ключи, по которым работает корреляция.
