# Отчёты по этапам

Каждый этап закрывается только после зелёного CI на Windows. Здесь — что реализовано, какие файлы затронуты, какие тесты пройдены и что осталось.

## Проверка сторонних разборщиков — 2026-11-08

**Реализовано.** Проверка библиотек MFT, Usn, Prefetch, JumpList (+ Lnk, OleCf, ExtensionBlocks, GuidMapping) по исходному коду; воспроизводимый стенд повреждённых данных; вердикты и условия подключения.

**Файлы.** `docs/LIBRARY_REVIEW.md`, `tools/lib-robustness/**`.

**Проверено.** 131 226 случаев повреждённых и усечённых данных, 3 зерна: 0 зависаний, 0 аварий процесса; 28 случаев разового выделения памяти больше 512 МБ (LNK, Jump Lists, запись MFT). CI подтвердил, что на nuget.org опубликованы MFT 2026.10.4, Prefetch 2026.10.1, JumpList 2026.10.10.

**Осталось.** Собственные тесты библиотек на Windows-раннере; образцы Prefetch версии 31 и Jump Lists с Windows 11.

## Этап 1 — Core и модели — 2026-11-08

**Реализовано.**

- `XINSkan.Models`: схема Evidence v1 (см. `docs/EVIDENCE_SCHEMA.md`) с проверкой инвариантов; ULID; SHA-256; метки времени с точностью и погрешностью; покрытие источника.
- `XINSkan.Core`: `InvestigationRunner` — модули по очереди, изоляция сбоев, пропуск при отсутствии прав или согласия, неотменяемая фиксация после каждого модуля, запрет записи чужих и запоздалых записей; `PermissionManager` с явными согласиями; `PathNormalizer` и `VolumeMap`.
- CI на `windows-latest`; офлайн-раннер тестов для изолированной среды.

**Файлы.** `src/XINSkan.Models/*`, `src/XINSkan.Core/**`, `tests/XINSkan.UnitTests/**`, `tools/offline-tests/*`, `.github/workflows/ci.yml`, `Directory.Build.props`, `Directory.Packages.props`, `global.json`, `XINSkan.slnx`, `README.md`, `docs/BUILD.md`, `docs/EVIDENCE_SCHEMA.md`.

**Тесты.** 93 из 93 на Windows (CI-запуск 42507885446, SDK 10.0.403, Windows 10.0.26100); те же 93 — офлайн-раннером на Linux. Сборка с анализаторами .NET в рекомендуемом режиме, предупреждения — ошибки.

Что доказывают тесты:

- сбой одного модуля не останавливает следующие;
- отмена сохраняет уже собранные записи, оставшиеся модули получают статус Cancelled с причиной, фиксация не принимает токен отмены;
- модуль без нужных прав или согласия пропускается с причиной; без согласия сетевой модуль не запускается;
- запись с уровнем High, с утверждением о запуске из MFT/USN/файловой системы, с неполным сбором без ограничений — отклоняется, модуль останавливается;
- модуль не может писать от имени другого модуля, в другую проверку или после завершения.

**Найдено тестами и исправлено.** `PathNormalizer.FileName("C:\")` возвращал `C:\` вместо пустого значения.

**Осталось.** CLI появится вместе с хранилищем (этап 3): без хранилища ему нечего сохранять. Время по-прежнему не синхронизируется с внешним источником — оценка расхождения часов будет в корреляции.

## Этап 2 — Read-Only Security — 2026-11-08

**Реализовано.**

- `XINSkan.Platform.Windows` — единственная сборка с системными вызовами (`CreateFileW`, `DeviceIoControl`, `GetVolumeInformationW`): `ReadOnlyFile` и `ReadOnlyHandleStream` (только чтение, полное разделение доступа), `VolumeReader` (выровненное сырое чтение тома, данные NTFS), `SafeIoControl` (шесть кодов запроса и чтения), `RegistryReader` (`OpenSubKey(string)`), `WindowsCapabilityProbe`.
- `XINSkan.Security` — `OutputSink` (новая папка на проверку, только `CreateNew`, без выхода за папку и без удаления), `OutputLocationPolicy`, `AuditLogger` с цепочкой хешей, `IntegrityManifest`.
- `BannedSymbols.txt` (82 запрета) + анализатор во всех сборках, которые должны только читать.
- Описание и пределы — `docs/SECURITY.md`.

**Файлы.** `src/XINSkan.Platform.Windows/**`, `src/XINSkan.Security/**`, `BannedSymbols.txt`, `Directory.Build.targets`, `Directory.Build.props`, `Directory.Packages.props`, `tests/XINSkan.SecurityTests/**`, `tests/XINSkan.NegativeBuild/**`, `.github/workflows/ci.yml`, `docs/SECURITY.md`, `README.md`, `XINSkan.slnx`.

**Тесты.** CI-запуск 42508982951 на Windows: 93 модульных + 57 тестов безопасности, все пройдены, ни один не пропущен. Отрицательная сборка дала 8 ошибок RS0030 — все четыре запрещённых вызова отмечены.

- **Измерение на настоящем NTFS** (виртуальный диск на раннере): после чтения файлов, загрузочного сектора, 16 записей MFT, данных NTFS и всех проб прав — позиция USN Journal, хеши, время создания и изменения, атрибуты файлов не изменились.
- Пока XIN SKAN держит файл открытым, другой процесс может его дописать, переименовать и удалить.
- Скомпилированный IL сборок Models, Core и Platform не содержит ни одного запрещённого вызова; все вызовы разрешены; сканер доказанно находит запрещённые вызовы там, где они есть.
- Каждый из 82 запретов указывает на существующий API (опечатка не может молча отключить запрет).
- В сборке Security запись файлов встречается только в `OutputSink` и `IntegrityManifest`.

**Ограничения, зафиксированные честно.** Цепочка аудита без внешней подписи не защищает от пересчёта всех хешей, а усечение хвоста журнала само по себе не обнаруживается (есть отдельный тест, фиксирующий это). Время последнего доступа файлов может меняться при чтении — поведение будет выведено в журнал CI при следующем запуске. Проверка журнала Security отложена до этапа источников журналов событий (TODO).

**Осталось.** Запреты на методы экспорта библиотек (`SavePrefetch`, `DumpAllLnkFiles`) — вместе с подключением библиотек; рабочий процесс-изолятор для разборщиков — на этапе History Engine.

## Этап 3 — Storage (SQLite) — 2026-11-08

**Реализовано.** `InvestigationStore` (реализует `IInvestigationSink` конвейера): отдельная база на проверку в её папке, файл базы и журнала заявляются через `OutputSink`, пакетная запись, фиксация модуля одной транзакцией вместе с его результатом, при ошибке записи ничего частичного не фиксируется и записи остаются в буфере. Триггеры запрещают `UPDATE` и `DELETE`. Представления `FileEvents` и `ExecutionEvents`. `InvestigationReader` открывает базу только для чтения. Резервная копия `BackupTo`. Описание — `docs/STORAGE.md`.

**Файлы.** `src/XINSkan.Storage/**`, `src/XINSkan.Models/InvestigationInfo.cs`, `src/XINSkan.Security/OutputSink.cs` (`ReserveNewFile`), `tests/XINSkan.StorageTests/**`, `Directory.Packages.props` (Microsoft.Data.Sqlite 10.0.14), `docs/STORAGE.md`.

**Тесты.** CI-запуск 42509951350: 93 + 57 + 16 = 166 тестов, все пройдены.

- Все поля свидетельства (кириллица в путях, 48-битная запись MFT, серийный номер тома больше `long`, доп. метки времени, ограничения, атрибуты) сохраняются и читаются без потерь, запись снова проходит проверку схемы.
- `UPDATE`/`DELETE` в свидетельствах, результатах модулей и заголовке отклоняются базой.
- Зафиксированное видно другим читателям до закрытия хранилища; незафиксированное — нет.
- Сквозной сценарий: конвейер → отмена во втором модуле → в базе 6 свидетельств, состояния «с ошибками / отменено / отменено», покрытие и ошибка модуля.
- Каждый файл папки проверки учтён `OutputSink`, манифест целостности сходится; вторая проверка не меняет первую; чтение не меняет хеш базы.

**Найдено замером и исправлено.** Первая версия сбрасывала каждый пакет на диск: 100 000 записей — 158 с. Теперь принудительный сброс только при фиксации модуля: 39 с (вставка 8,3 с, фиксации 30,4 с за 21 транзакцию). Цена — описана в `docs/STORAGE.md`: при отключении питания посреди модуля может потеряться его незафиксированная часть.

**Осталось.** Скорость фиксаций на Windows-раннере всё ещё около 1,5 с на транзакцию; для источников с миллионами записей (MFT) это нужно улучшить — кандидат: режим WAL с учётом его служебных файлов в `OutputSink`. Таблицы сетевого модуля, сигнатур, корреляции и отчётов — в своих этапах.
