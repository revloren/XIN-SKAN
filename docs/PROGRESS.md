# Отчёты по этапам

Каждый этап закрывается только после зелёного CI на Windows. Здесь — что реализовано, какие файлы затронуты, какие тесты пройдены и что осталось.

## Проверка сторонних разборщиков — 2026-11-08

**Реализовано.** Проверка библиотек MFT, Usn, Prefetch, JumpList (+ Lnk, OleCf, ExtensionBlocks, GuidMapping) по исходному коду; воспроизводимый стенд повреждённых данных; вердикты и условия подключения.

**Файлы.** `docs/LIBRARY_REVIEW.md`, `tools/lib-robustness/**`.

**Проверено.** 131 226 случаев повреждённых и усечённых данных, 3 зерна: 0 зависаний, 0 аварий процесса; 28 случаев разового выделения памяти больше 512 МБ (LNK, Jump Lists, запись MFT). CI подтвердил, что на nuget.org опубликованы MFT 2026.10.4, Prefetch 2026.10.1, JumpList 2026.10.10.

**Осталось.** Собственные тесты библиотек на Windows-раннере; образцы Prefetch версии 31 и Jump Lists с Windows 11.

## Этап 1 — Core и модели — 2026-11-08

**Реализовано.**

- `XINSkan.Models`: схема Evidence v1 (см. `docs/EVIDENCE_SCHEMA.md`) с проверкой инвариантов; ULID; SHA-256; метки времени с точностью и погрешностью; покрытие источника.
- `XINSkan.Core`: `InvestigationRunner` — модули по очереди, изоляция сбоев, пропуск при отсутствии прав или согласия, неотменяемая фиксация после каждого модуля, запрет записи чужих и запоздалых записей; `PermissionManager` с явными согласиями; `PathNormalizer` и `VolumeMap`.
- CI на `windows-latest`; офлайн-раннер тестов для изолированной среды.

**Файлы.** `src/XINSkan.Models/*`, `src/XINSkan.Core/**`, `tests/XINSkan.UnitTests/**`, `tools/offline-tests/*`, `.github/workflows/ci.yml`, `Directory.Build.props`, `Directory.Packages.props`, `global.json`, `XINSkan.slnx`, `README.md`, `docs/BUILD.md`, `docs/EVIDENCE_SCHEMA.md`.

**Тесты.** 93 из 93 на Windows (CI-запуск 42507885446, SDK 10.0.403, Windows 10.0.26100); те же 93 — офлайн-раннером на Linux. Сборка с анализаторами .NET в рекомендуемом режиме, предупреждения — ошибки.

Что доказывают тесты:

- сбой одного модуля не останавливает следующие;
- отмена сохраняет уже собранные записи, оставшиеся модули получают статус Cancelled с причиной, фиксация не принимает токен отмены;
- модуль без нужных прав или согласия пропускается с причиной; без согласия сетевой модуль не запускается;
- запись с уровнем High, с утверждением о запуске из MFT/USN/файловой системы, с неполным сбором без ограничений — отклоняется, модуль останавливается;
- модуль не может писать от имени другого модуля, в другую проверку или после завершения.

**Найдено тестами и исправлено.** `PathNormalizer.FileName("C:\")` возвращал `C:\` вместо пустого значения.

**Осталось.** CLI появится вместе с хранилищем (этап 3): без хранилища ему нечего сохранять. Время по-прежнему не синхронизируется с внешним источником — оценка расхождения часов будет в корреляции.

## Этап 2 — Read-Only Security — 2026-11-08

**Реализовано.**

- `XINSkan.Platform.Windows` — единственная сборка с системными вызовами (`CreateFileW`, `DeviceIoControl`, `GetVolumeInformationW`): `ReadOnlyFile` и `ReadOnlyHandleStream` (только чтение, полное разделение доступа), `VolumeReader` (выровненное сырое чтение тома, данные NTFS), `SafeIoControl` (шесть кодов запроса и чтения), `RegistryReader` (`OpenSubKey(string)`), `WindowsCapabilityProbe`.
- `XINSkan.Security` — `OutputSink` (новая папка на проверку, только `CreateNew`, без выхода за папку и без удаления), `OutputLocationPolicy`, `AuditLogger` с цепочкой хешей, `IntegrityManifest`.
- `BannedSymbols.txt` (82 запрета) + анализатор во всех сборках, которые должны только читать.
- Описание и пределы — `docs/SECURITY.md`.

**Файлы.** `src/XINSkan.Platform.Windows/**`, `src/XINSkan.Security/**`, `BannedSymbols.txt`, `Directory.Build.targets`, `Directory.Build.props`, `Directory.Packages.props`, `tests/XINSkan.SecurityTests/**`, `tests/XINSkan.NegativeBuild/**`, `.github/workflows/ci.yml`, `docs/SECURITY.md`, `README.md`, `XINSkan.slnx`.

**Тесты.** CI-запуск 42508982951 на Windows: 93 модульных + 57 тестов безопасности, все пройдены, ни один не пропущен. Отрицательная сборка дала 8 ошибок RS0030 — все четыре запрещённых вызова отмечены.

- **Измерение на настоящем NTFS** (виртуальный диск на раннере): после чтения файлов, загрузочного сектора, 16 записей MFT, данных NTFS и всех проб прав — позиция USN Journal, хеши, время создания и изменения, атрибуты файлов не изменились.
- Пока XIN SKAN держит файл открытым, другой процесс может его дописать, переименовать и удалить.
- Скомпилированный IL сборок Models, Core и Platform не содержит ни одного запрещённого вызова; все вызовы разрешены; сканер доказанно находит запрещённые вызовы там, где они есть.
- Каждый из 82 запретов указывает на существующий API (опечатка не может молча отключить запрет).
- В сборке Security запись файлов встречается только в `OutputSink` и `IntegrityManifest`.

**Ограничения, зафиксированные честно.** Цепочка аудита без внешней подписи не защищает от пересчёта всех хешей, а усечение хвоста журнала само по себе не обнаруживается (есть отдельный тест, фиксирующий это). Время последнего доступа файлов может меняться при чтении — поведение будет выведено в журнал CI при следующем запуске. Проверка журнала Security отложена до этапа источников журналов событий (TODO).

**Осталось.** Запреты на методы экспорта библиотек (`SavePrefetch`, `DumpAllLnkFiles`) — вместе с подключением библиотек; рабочий процесс-изолятор для разборщиков — на этапе History Engine.

## Этап 3 — Storage (SQLite) — 2026-11-08

**Реализовано.** `InvestigationStore` (реализует `IInvestigationSink` конвейера): отдельная база на проверку в её папке, файл базы и журнала заявляются через `OutputSink`, пакетная запись, фиксация модуля одной транзакцией вместе с его результатом, при ошибке записи ничего частичного не фиксируется и записи остаются в буфере. Триггеры запрещают `UPDATE` и `DELETE`. Представления `FileEvents` и `ExecutionEvents`. `InvestigationReader` открывает базу только для чтения. Резервная копия `BackupTo`. Описание — `docs/STORAGE.md`.

**Файлы.** `src/XINSkan.Storage/**`, `src/XINSkan.Models/InvestigationInfo.cs`, `src/XINSkan.Security/OutputSink.cs` (`ReserveNewFile`), `tests/XINSkan.StorageTests/**`, `Directory.Packages.props` (Microsoft.Data.Sqlite 10.0.14), `docs/STORAGE.md`.

**Тесты.** CI-запуск 42509951350: 93 + 57 + 16 = 166 тестов, все пройдены.

- Все поля свидетельства (кириллица в путях, 48-битная запись MFT, серийный номер тома больше `long`, доп. метки времени, ограничения, атрибуты) сохраняются и читаются без потерь, запись снова проходит проверку схемы.
- `UPDATE`/`DELETE` в свидетельствах, результатах модулей и заголовке отклоняются базой.
- Зафиксированное видно другим читателям до закрытия хранилища; незафиксированное — нет.
- Сквозной сценарий: конвейер → отмена во втором модуле → в базе 6 свидетельств, состояния «с ошибками / отменено / отменено», покрытие и ошибка модуля.
- Каждый файл папки проверки учтён `OutputSink`, манифест целостности сходится; вторая проверка не меняет первую; чтение не меняет хеш базы.

**Найдено замером и исправлено.** Первая версия сбрасывала каждый пакет на диск: 100 000 записей — 158 с. Теперь принудительный сброс только при фиксации модуля: 39 с (вставка 8,3 с, фиксации 30,4 с за 21 транзакцию). Цена — описана в `docs/STORAGE.md`: при отключении питания посреди модуля может потеряться его незафиксированная часть.

**Осталось.** Скорость фиксаций на Windows-раннере всё ещё около 1,5 с на транзакцию; для источников с миллионами записей (MFT) это нужно улучшить — кандидат: режим WAL с учётом его служебных файлов в `OutputSink`. Таблицы сетевого модуля, сигнатур, корреляции и отчётов — в своих этапах.

## Каркас интерфейса — 2026-11-08

**Реализовано.** WPF-приложение `XINSkan.App` (net10.0-windows): навигация из стеклянных плиток, оранжевый градиент только на главной кнопке, Bahnschrift для заголовков и чисел, тёмные полосы прокрутки и выпадающие списки. Экраны: Обзор, Проверка, Хронология, Отчёты, База клиентов, Сеть, Настройки.

**Только настоящие данные.** Готовность системы — живые пробы прав (`WindowsCapabilityProbe`); проверки, хронология и отчёты — чтение баз проверок только для чтения и сверка с манифестом целостности; статусы модулей — из `ModuleCatalog`, где ни один анализатор не помечен готовым. Кнопка «Начать проверку» неактивна и объясняет почему. Экраны будущих модулей прямо пишут, на каком этапе они появятся, и не показывают пустых результатов. Настройки не сохраняются на диск: запись файла изменила бы исследуемый компьютер; папка результатов по умолчанию — рядом с программой (удобно для запуска с флешки).

**Тесты.** CI-запуск 42511280149: 93 + 57 + 16 + 6 = 172 теста. `AppTests`: каталог не объявляет анализаторы готовыми; библиотека проверок читает настоящую базу и различает «не закрыта / подтверждена / нарушена / не читается»; визуальный тест открывает настоящее окно, проходит все 7 экранов, падает на любой ошибке привязки данных и выводит снимки экранов в журнал CI.

**Найдено по снимкам и исправлено.** Светлые системные полосы прокрутки и выпадающий список на тёмном фоне; технические английские тексты проб и оценки папки посреди русского интерфейса (английский текст сохранён во всплывающей подсказке); пустота в карточке последней проверки; поле фильтра без подсказки.

**Осталось.** Экран проверки с прогрессом и отменой — вместе с первым анализатором (этап 4); выбор папки через диалог; проверка на экранах с высоким DPI.

## Этап 4 — File Hunter — 2026-11-09

**Реализовано.**

- `XINSkan.Analyzers.FileHunter`: обход всех профилей пользователей (другие — только при доступе), `C:\Windows\Temp` и папок оператора; ссылки не проходятся; отбор — всё в папках Minecraft, архивы и исполняемые по расширению, и в местах загрузок — файлы, которые по содержимому являются ZIP/JAR, PE или классом Java (находит JAR, переименованный в `.txt`). Для каждого файла: тип по сигнатуре, SHA-256, идентификатор NTFS (том, запись MFT, sequence) с того же дескриптора, описатели модов Fabric/Quilt/Forge/старого Forge, манифест JAR (в том числе Java-агенты), пакеты классов и вложенные JAR, ресурс версии PE (исходное имя файла), Authenticode без сети, `Zone.Identifier`. Все записи — Informational, `FS.SI_TIMES` всегда. Подробно — `docs/FILE_HUNTER.md`.
- Платформа: `WindowsFileSource` (тот же `CreateFileW` только на чтение; длинные пути; альтернативные потоки), `AuthenticodeVerifier` (`WinVerifyTrust` без интерфейса и без проверки отзыва). Список разрешённых системных вызовов дополнен `GetFileInformationByHandle` и `WinVerifyTrust`.
- `XINSkan.Investigation`: одна проверка целиком — новая папка → журнал аудита (каждая прочитанная папка и открытый файл, пробы прав, согласия) → база → File Hunter → закрытие базы → манифест → пометка файлов «только чтение» → самопроверка манифеста.
- `xinskan investigate` / `xinskan verify` (манифест, цепочка аудита, база, сводка записей).
- Приложение: «Начать проверку», отмена, ход и итог; после проверки обзор, хронология и отчёты перечитывают папку. File Hunter отмечен готовым в каталоге модулей.

**Найдено при работе и исправлено.**

- Отказ хранилища во время работы модуля конвейер считал сбоем модуля и продолжал проверку, хотя документация обещала остановку. Теперь `InvestigationSinkException` останавливает проверку, даже если анализатор перехватил исключение или превратил его в отмену (3 новых теста конвейера). Первая версия исправления не ловила синхронные исключения хранилища — это поймали эти же тесты.
- Два теста на виртуальных дисках из разных тестовых сборок выбирали одну букву диска одновременно. Создание диска теперь сериализовано между процессами.
- Анализатор мог зависнуть, если обработчик падал при заполненной очереди (исправлено до первого коммита, есть тест).

**Файлы.** `src/XINSkan.Analyzers.FileHunter/**`, `src/XINSkan.Investigation/**`, `src/XINSkan.Cli/**`, `src/XINSkan.Core/IO/FileSystemAbstractions.cs`, `src/XINSkan.Core/Pipeline/{InvestigationRunner,ModuleEvidenceWriter}.cs`, `src/XINSkan.Platform.Windows/{AuthenticodeVerifier.cs,IO/WindowsFileSource.cs,IO/ReadOnlyFile.cs,Native/NativeMethods.cs}`, `src/XINSkan.App/{Services/InvestigationLauncher.cs,Services/AppEnvironment.cs,Services/ModuleCatalog.cs,ViewModels/ViewModels.cs,Views/InvestigationView.xaml,XINSkan.App.csproj}`, `tests/XINSkan.FileHunterTests/**`, `tests/XINSkan.InvestigationTests/**`, `tests/XINSkan.UnitTests/{Core/InvestigationRunnerTests.cs,TestDoubles.cs}`, `tests/XINSkan.SecurityTests/{ReadOnlyEnforcementTests.cs,Windows/TestVhd.cs}`, `tests/XINSkan.AppTests/AppDataTests.cs`, `tools/offline-tests/*`, `.github/workflows/ci.yml`, `XINSkan.slnx`, `docs/{FILE_HUNTER,SECURITY,PROGRESS}.md`, `README.md`.

**Тесты.** CI-запуск 42543702092: 225 из 225 (модульные 96, безопасность 57, File Hunter 43, хранилище 16, сервис проверки 7, интерфейс 6), ни один не пропущен.

- Сценарий профиля игрока: записан ровно ожидаемый набор файлов и папок; обычные файлы вне мест загрузок даже не открываются; хеши совпадают; метаданные модов, Java-агент, переименованный архив, исходное имя исполняемого файла; повреждённый архив — Partial, модуль продолжает; петля из ссылки не проходится и отражена в покрытии; профили других пользователей — только при доступе; недоступные папки посчитаны, отдельных ошибок не больше 50; занятый файл записан с метаданными; предел хеша; происхождение загрузки; отмена; 20 тыс. объектов за 0,1 с.

- Сервис проверки: папка закрыта манифестом, цепочка аудита цела, каждый записанный файл есть в аудите; вторая проверка не меняет первую; отмена сохраняет записи и закрывает папку; отказ хранилища — исключение, папка без манифеста; с настоящей SQLite в базе ровно то, что нашёл File Hunter.
- **Настоящий прогон на раннере** (CLI): 3 445 записей, `verify` — манифест сходится, цепочка аудита цела (4 821 запись); второй прогон не изменил папку первого. Время — в `docs/FILE_HUNTER.md`: 183 с на холодном диске, 7,1 с на прочитанном.

**Ограничения, зафиксированные честно.**

- `NotSigned` означает «нет встроенной подписи»: файлы, подписанные через каталоги Windows, тоже `NotSigned` (TODO: проверка по каталогу и имя подписавшего).
- Время из `$STANDARD_INFORMATION`; сверка с `$FILE_NAME`, удалённые и переименованные файлы — только в History Engine.
- Путь запуска из интерфейса проверен сборкой и тем же сервисом, что и CLI, но состояние «идёт проверка» визуальным тестом не снимается.
- Адрес загрузки из `Zone.Identifier` записывается целиком — решение по приватности за владельцем.

**Осталось.** Этап 5 — History Engine.

## Этап 5 — History Engine (частично) — 2026-11-09

**Реализовано.** Восемь модулей, все подключены к проверке (приложение и CLI), подробно — `docs/HISTORY_ENGINE.md`.

- `XINSkan.Ntfs` — собственный разбор NTFS без ввода-вывода: записи MFT (проверка секторов, `$SI`, `$FN` всех пространств имён, `$DATA` с потоками и резидентным содержимым, резидентный `$ATTRIBUTE_LIST`, атрибуты свободных записей за занятым размером), цепочки кластеров, потоковое чтение `$MFT` по его собственной записи 0, компактная карта путей (~13 байт на запись) с честной оценкой пути, записи USN v2/v3 и данные журнала.
- `XINSkan.ShellFormats` — собственный разбор с жёсткими границами: элементы оболочки (BEEF0004 v3–v9 с номером записи MFT), ярлыки, составные файлы OLE, DestList v1/v3+, customDestinations.
- Модули `mft`, `usn`, `recycle-bin`, `minecraft-logs`, `lnk`, `jumplists`, `shellbags`. Платформа: чтение USN Journal, `RegQueryInfoKeyW` (время записи ключа, только чтение). Аудит: открытие тома, запросы и чтение журнала, чтение деревьев ShellBags.
- Каталог модулей: History Engine — «Частично» (нет теневых копий и ShellBags других пользователей).

**Что выяснилось на реальных данных и было исправлено.**

- Первый прогон USN на профиле CI-машины дал 11 551 событие, почти все — DLL установщиков, и 248 записей Low за переименования `.tmp` → `.dll`. Правила отбора переписаны: полная жизнь — только для папок Minecraft, Java-архивов и мест загрузок; Low — только за потерю «говорящего» расширения; завершение загрузки (`.crdownload` → `.jar`) — Downloaded. Стало 1 156 событий.
- Windows отдаёт освобождённую запись MFT следующему файлу почти сразу: на тестовом томе новый файл дважды занял запись только что удалённого мода. Тестовые сценарии перестроены, в покрытии MFT это сказано прямо.
