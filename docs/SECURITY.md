# Read-Only by Design

XIN SKAN только читает исследуемую систему. В приложении нет функций удаления, очистки, остановки процессов, изменения сети, брандмауэра или реестра. Это обеспечивается не одним классом-«охранником», а четырьмя слоями, каждый из которых проверяется автоматически.

## Слои защиты

| Слой | Как устроен | Чем проверяется |
| --- | --- | --- |
| 1. Интерфейсы без записи | Исследуемые файлы открываются только через `ReadOnlyFile` (GENERIC_READ, разделение чтение/запись/удаление, OPEN_EXISTING). Поток `ReadOnlyHandleStream` не умеет писать. Тома — через `VolumeReader`, реестр — через `RegistryReader` с `OpenSubKey(string)`. Перегрузок с режимом доступа нет. | `ReadOnlyEnforcementTests.Files_and_volumes_are_opened_with_read_access_and_full_sharing`, `ReadOnlyHandleStreamTests` |
| 2. Запрет при компиляции | `BannedSymbols.txt` + `Microsoft.CodeAnalysis.BannedApiAnalyzers` во всех сборках с `XinEnforceReadOnly=true` (по умолчанию — все, кроме Security, Storage, Reporting и тестов). Нарушение — ошибка RS0030. | CI собирает `tests/XINSkan.NegativeBuild` с четырьмя запрещёнными вызовами и падает, если сборка прошла или хотя бы один вызов не отмечен. `Every_banned_symbol_resolves_to_a_real_api` не даёт опечатке молча отключить запрет. |
| 3. Проверка скомпилированного IL | Сканер разбирает IL всех методов, включая сгенерированные компилятором (лямбды, async, итераторы), и разрешает каждый вызов. | `Read_only_assemblies_contain_no_banned_calls`, `All_calls_in_read_only_assemblies_can_be_resolved`, `Scanner_detects_a_banned_call_when_one_exists` (сканер не «слепой»), `In_the_security_assembly_only_the_output_writers_touch_the_file_system` |

## Куда пишет XIN SKAN

Единственный класс, создающий файлы, — `OutputSink`:

- каждая проверка получает **новую** папку; существующая папка не используется повторно;
- файлы создаются только с `FileMode.CreateNew` — повторная запись того же имени невозможна, поэтому прежние отчёты не перезаписываются;
- пути с `..`, `.`, буквой диска, абсолютные и с альтернативными потоками (`:`) отклоняются;
- удаления нет.

`OutputLocationPolicy` предупреждает, если папка вывода лежит на исследуемом томе: новые файлы могут занять кластеры, где ещё есть содержимое удалённых файлов, и появятся в его USN Journal. Рекомендуется внешний носитель.

## Журнал аудита и целостность результатов

- `AuditLogger` — JSON Lines, каждая строка содержит SHA-256 предыдущей. Изменённая, удалённая из середины или переставленная строка обнаруживается.
- `IntegrityManifest` — SHA-256 всех файлов проверки; при проверке сообщает об изменённых, отсутствующих и добавленных файлах.

**Пределы, которые нужно понимать:**

- Цепочка хешей без внешней подписи не защищает от того, кто пересчитает все хеши заново. Это защита от случайной порчи и наивного редактирования.
- Отбрасывание последних строк журнала оставляет корректную короткую цепочку (тест `Truncated_tail_is_not_detected_without_an_external_anchor` фиксирует это явно). Хеш манифеста, показанный оператору и напечатанный в отчёте, закрывает этот разрыв, только если его сохранили вне компьютера.
- Атрибут «только чтение» на готовых файлах — защита от случайной правки, а не от умысла.

## Неизбежный собственный след

XIN SKAN не может быть полностью невидимым для Windows. Каждый отчёт будет перечислять:

- записи Prefetch, BAM и Amcache о запуске самого XIN SKAN;
- события входа с особыми правами в журнале Security, если на компьютере включён аудит;
- **время последнего доступа** прочитанных файлов может измениться, если NTFS обновляет его на этом томе. Запретить это можно только хендлом с правом FILE_WRITE_ATTRIBUTES, а такой хендл XIN SKAN не открывает. `VolumeImmutabilityTests` фиксирует фактическое поведение в журнале теста;
- новые записи MFT и USN, если вывод сохраняется на исследуемый том;
- ETW-сессия на время сетевого мониторинга — только после согласия (будущий этап).

Теневые копии XIN SKAN не создаёт. Занятые системой файлы (`Amcache.hve`, `SRUDB.dat`, `UsrClass.dat`) будут читаться через `VolumeReader` по карте кластеров, без копирования средствами Windows и без остановки служб.

## Разрешения и согласия

`PermissionManager` один раз проверяет права (администратор, сырое чтение тома, USN Journal, защищённые ключи реестра, чужие профили) и хранит согласия владельца: кто, когда и на какой текст согласился. По умолчанию не дано ни одно согласие. Модуль без нужного права или согласия не запускается и получает статус Skipped с причиной.

Проверка журнала Security пока не реализована и всегда сообщает «недоступно» с пометкой TODO — до этапа, где появится источник журналов событий.

## Сторонние разборщики

Библиотеки MFT, Prefetch и Jump Lists содержат методы экспорта, которые пишут файлы (`PrefetchFile.SavePrefetch`, `DumpAllLnkFiles`). Их вызов будет добавлен в `BannedSymbols.txt` вместе с подключением библиотек, а разбор пользовательских артефактов пойдёт в отдельном процессе с лимитом памяти — см. `docs/LIBRARY_REVIEW.md`.
