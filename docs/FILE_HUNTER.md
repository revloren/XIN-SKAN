# File Hunter

File Hunter записывает существующие файлы и папки, которые могут иметь значение для проверки Minecraft: что это за содержимое, его SHA-256, идентификатор NTFS, встроенные метаданные, подпись и происхождение загрузки. Наличие файла само по себе ничего не доказывает: **каждая запись имеет уровень Informational**. Оценки появятся только после корреляции с историей и следами запуска (этапы 5–7) и с проверенной базой (этап 9).

## Где ищет

| Корень | Что входит | Условие |
| --- | --- | --- |
| Профиль текущего пользователя | весь профиль целиком | всегда |
| Профили других пользователей | весь профиль целиком | только при доступе `OtherUserProfiles` (обычно права администратора) |
| `C:\Windows\Temp` | вся папка | если существует |
| Дополнительные папки оператора | вся папка | `--extra` в CLI |

Пропускаются системные профили (`Default`, `Default User`, `All Users`, `Public`, `defaultuser0`, `WDAGUtilityAccount`). Каждая исключённая область записывается в покрытие с причиной (`SCOPE.EXCLUDED`).

Сканируется весь профиль, а не список известных папок лаунчеров: клиент, сложенный в `D:\Игры\что-угодно` или `Профиль\Games\Custom`, иначе был бы пропущен.

**Ссылки не проходятся** (точки повторной обработки, символические ссылки, соединения). Это исключает петли и выход за пределы области; число непройденных ссылок записывается в покрытие (`FS.LINKS`), а каждая такая запись получает ограничение `LINK.NOT_FOLLOWED`.

## Что записывает

| Отбор (`Selection`) | Правило |
| --- | --- |
| `MinecraftTree` | Всё внутри папки игры: `.minecraft` или папка, где рядом лежат `options.txt` и `mods`/`versions`/`saves`. Записываются и файлы, и папки. |
| `ExecutableOrArchive` | Файлы `.jar .zip .exe .dll .mrpack` в любом месте области. |
| `DropLocationContent` | Файлы в местах, куда попадают загрузки (`Downloads`, `Desktop`, `Documents`, `AppData\Local\Temp`, `OneDrive\Desktop`, `OneDrive\Documents`, корень профиля, временные папки системы) — **только если по содержимому это ZIP/JAR, PE или класс Java**. Так находится JAR, переименованный в `.txt`. |

Остальные файлы не открываются вовсе (это проверяет тест `Ordinary_files_outside_drop_locations_are_not_even_opened`).

## Содержимое записи

Все файлы открываются только через платформенный слой (`GENERIC_READ`, полное разделение доступа, без изменения файла); идентификатор NTFS берётся с того же дескриптора, которым читается содержимое.

| Атрибут | Значение |
| --- | --- |
| `Selection`, `MinecraftRoot` | почему запись сделана; корень игры |
| `Content`, `ExtensionMismatch` | тип по сигнатуре (Zip / PortableExecutable / JavaClass / …); расхождение с расширением |
| `FileAttributes` | только если есть Hidden, System или ReparsePoint |
| `Archive.Entries`, `Archive.Classes` | число записей и классов в архиве |
| `Mod.Loader`, `Mod.Id`, `Mod.Name`, `Mod.Version` | из `fabric.mod.json`, `quilt.mod.json`, `META-INF/mods.toml`, `mcmod.info` |
| `Manifest.*` | `Main-Class`, `Premain-Class`, `Agent-Class`, `Launcher-Agent-Class`, `Can-Retransform-Classes` и т. п. (Java-агент — признак для дальнейшего анализа, не вывод) |
| `Jar.TopPackages`, `Jar.Nested`, `Jar.NestedMods` | основные пакеты классов; вложенные JAR и моды в них |
| `Pe.Machine`, `Pe.Kind`, `Pe.DotNet`, `Pe.FileVersion`, `Pe.*` из ресурса версии | `OriginalFilename`, `ProductName`, `CompanyName` и др. — видно, если исполняемый файл переименован |
| `Signature`, `SignatureDetail` | Authenticode: `Valid`, `NotSigned`, `Tampered`, `Untrusted`, `Error` |
| `Zone.Id`, `Zone.HostUrl`, `Zone.ReferrerUrl` | из потока `Zone.Identifier` — откуда файл был скачан |

Хеш — SHA-256 содержимого файла (`ObjectSha256`), для файлов до 256 МБ.

## Ограничения, которые указываются в записях

| Код | Смысл |
| --- | --- |
| `FS.SI_TIMES` | Время взято из `$STANDARD_INFORMATION` и может быть изменено программно. Сверка с `$FILE_NAME` — в History Engine. Ставится всегда. |
| `LINK.NOT_FOLLOWED` | Объект — ссылка; её цель не проверялась. |
| `CONTENT.ACCESS_DENIED`, `CONTENT.UNREADABLE` | Файл занят или закрыт; записаны только метаданные. |
| `CONTENT.CHANGING` | Размер файла изменился во время чтения; хеш может не соответствовать ни одному состоянию. |
| `HASH.SIZE_LIMIT` | Файл больше предела, хеш не считался. |
| `ARCHIVE.PARTIAL`, `PE.PARTIAL` | Архив или заголовки PE повреждены; прочитано, что удалось. |
| `ZONE.UNREADABLE` | Поток `Zone.Identifier` есть, но не прочитан. |

Покрытие (`SourceCoverage`) пишется на каждый корень: сколько объектов просмотрено, сколько записано, сколько папок не прочитано (`FS.INACCESSIBLE`), сколько ссылок не пройдено. Отдельных ошибок доступа записывается не больше 50; остальные учтены числом.

## Пределы разбора (защита от «архивных бомб» и повреждённых файлов)

Архив: не больше 200 000 записей (число берётся из конца архива до разбора), описатель мода не больше 1 МБ, вложенный JAR не больше 32 МБ и не больше 32 вложенных JAR. PE: каждый переход по таблицам проверяется на выход за границы, ресурс версии не больше 64 КБ. Тесты прогоняют 2000 испорченных архивов и 1500 испорченных PE: ни одного исключения наружу, ни одного зависания.

## Чего File Hunter не делает (и где это будет)

- **Удалённые и переименованные файлы** — History Engine (MFT, USN Journal, Корзина), этап 5.
- **Сверка времени `$STANDARD_INFORMATION` с `$FILE_NAME`** — там же.
- **Факт запуска** — Execution Engine, этап 6. Файл на диске не значит, что его запускали.
- **Имя подписавшего и подписи из каталогов Windows** — TODO. Сейчас `NotSigned` означает «нет встроенной подписи»: системные файлы, подписанные через каталог, тоже получат `NotSigned`, и это написано в `SignatureDetail`.
- **Перечисление через MFT** вместо обхода папок (быстрее и видит скрытое от API) — вместе с разбором MFT на этапе 5.
- **Сопоставление с базой известных клиентов** — этап 9.

## Конфиденциальность

Поток `Zone.Identifier` может содержать адрес страницы, с которой скачан файл. Он записывается только для отобранных файлов (архивы, исполняемые, файлы в папках игры). Решение о том, оставлять ли адрес целиком или только домен, остаётся за владельцем проекта.

## Как запускается

- **Приложение**: страница «Проверка» → «Начать проверку». Видны ход, кнопка отмены и итог.
- **Командная строка**: `xinskan investigate --output E:\XINSKAN [--extra D:\Games] [--operator Имя]`, затем `xinskan verify <папка проверки>`.

Обе точки входа используют `XINSkan.Investigation.InvestigationService`: новая папка → журнал аудита (каждая прочитанная папка и открытый файл) → база → права → File Hunter → закрытие базы → манифест SHA-256 → файлы помечаются «только чтение». Отмена не теряет собранного и закрывает папку манифестом; сбой хранилища останавливает проверку и оставляет папку без манифеста, чтобы она была видна как незакрытая.
