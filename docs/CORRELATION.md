# Корреляция свидетельств

Корреляция выполняется после всех модулей и связывает записи разных источников, которые описывают **один и тот же файл**, а затем применяет опубликованные правила. Записи не меняются: объекты и находки только ссылаются на них по ID и хранятся в отдельных таблицах той же базы (схема 3, `docs/STORAGE.md`). Совпадения с базой клиентов (`docs/SIGNATURE_DATABASE.md`) приходят в корреляцию вместе с фактами. Код: `src/XINSkan.Correlation`.

## Что корреляция не делает

- **Не определяет, что файл — чит, сама.** Идентификация — задача базы клиентов (этап 9); правила корреляции без совпадения с базой не называют клиентов.
- **Не ставит High без идентификации.** Уровень High требует трёх независимых семейств источников *и* проверенной идентификации объекта — точного хеша или компонента, подтверждённого исходным кодом проекта (`Finding.Validate` это проверяет). Совпадение одного названия идентификацией не считается.
- **Не заменяет записи.** В каждой находке перечислены записи-основания (`basis`) и записи для контекста (`context`), а в обосновании — безобидные объяснения.

## Связывание

1. **По ссылке MFT.** Том, номер записи и номер последовательности. Том — буква диска из пути; если пути нет (удалённая запись MFT с неизвестной папкой), используется серийный номер тома, сопоставленный с буквой по записям, где есть и то и другое. Так связываются File Hunter, MFT, USN, Prefetch (ссылки файлов запуска), Amcache старого формата и элементы оболочки.
2. **По пути.** Нормализованный путь (`PathNormalizer`), а также прежний путь из переименования в USN. Связь по пути **не делается**, если она соединила бы две разные ссылки MFT. Если по одному пути в разное время были разные файлы, запись без ссылки ни к одному не привязывается, и это записано в ограничения (`CORR.AMBIGUOUS_PATH`).

Состояние системы (очищенный журнал, исключение Защитника, выключенный Prefetch, пересозданный журнал USN) объектом не считается — оно участвует только в правилах о времени.

Объект хранится, если связал хотя бы две записи. У объекта — путь для чтения, другие пути (переименования), ссылка MFT, хеш, первое и последнее время и **семейства источников**.

## Независимые семейства

Источники, у которых разные писатель и структура, считаются независимыми:

| Семейство | Источники |
| --- | --- |
| `files` | File Hunter, `Zone.Identifier` |
| `mft` | записи MFT |
| `usn` | журнал изменений |
| `recycle-bin` | Корзина |
| `shell` | ярлыки, Jump Lists, ShellBags |
| `prefetch` | Prefetch |
| `bam` | BAM |
| `userassist` | UserAssist |
| `amcache` | Amcache |
| `defender` | журнал Microsoft Defender |
| `eventlog` | журналы System, Security, Application |
| `minecraft-log` | логи Minecraft |
| `launcher` | настройки лаунчеров и файлы версий (Minecraft Integrity) |

**Политика уровней.** Правило даёт Low. Medium — только если основание охватывает два независимых семейства или больше; иначе правило само понижается до Low. Исключение — прямая идентификация (`SIGNATURE_MATCH` с точным хешем или проверенным компонентом): она описывает сам файл и Medium с одним источником. High — только `KNOWN_CLIENT_ACTIVITY` с тремя семействами.

## Правила

| Правило | Когда | Уровень | Безобидные объяснения в обосновании |
| --- | --- | --- | --- |
| `TIMESTOMP_CONFIRMED` | у объекта расхождение `$SI`/`$FN` в MFT **и** смена времени в USN | Medium (`mft` + `usn`) | распаковка архива с сохранением дат, копирование |
| `RAN_THEN_DELETED` | след запуска или загрузки, затем удаление (USN, MFT, Корзина); отмечается удаление меньше чем за сутки до проверки | Low всегда | обновление, удаление ненужного |
| `HIDDEN_BY_RENAME` | потеря «говорящего» расширения (`.jar` → `.txt`) у файла, который запускался или загружался | Medium (`usn` + запуск) | отключение мода переименованием, резервная копия |
| `DEFENDER_FLAGGED_AND_RAN` | обнаружение Защитника и след запуска из другого семейства | Medium | HackTool и PUA — классификация, а не вывод |
| `EXCLUDED_AND_RAN` | исключение Защитника для папки (не корня диска), из которой что-то запускалось | Medium (`defender` + запуск) | исключения для игр, модов, разработки |
| `CONCEALMENT_CLUSTER` | признаки сокрытия из **двух разных семейств** в пределах 2 часов: очистка журнала, выключение защиты, исключение, пересоздание журнала USN; удаления в это окно — контекст | Medium | обслуживание, установка программ, работа администратора |
| `AGENT_CONFIRMED` | агент из настроек лаунчера (`-javaagent` и др., `docs/MINECRAFT_INTEGRITY.md`) и след его загрузки из другого семейства | Medium (`launcher` + загрузка) | профилировщики, агенты оптимизации |
| `MODIFIED_FILE_LOADED` | файл игры отличается от хеша в файле версии и загружался | Medium | старые моды в JAR, собственные сборки лаунчеров |
| `REMOVABLE_RUN` | запуск с тома, которого сейчас нет, и ярлыки на этот же том (по серийному номеру) | Low | запуск с флешки — не нарушение, но её содержимое не проверить |
| `SIGNATURE_MATCH` | запись совпала с базой клиентов (`docs/SIGNATURE_DATABASE.md`) | Medium — точный хеш или компонент проверенной записи; Low — однозначное название; справочный — лаунчер, общее слово, возможное совпадение | одноимённые проекты, файлы с похожими названиями, лаунчер — не нарушение |
| `FEATURE_SET_LOADED` | JAR с набором функций чит-клиента (`MultipleFeatureMatch`) и его загрузка или запуск из другого семейства | Medium; High невозможен — клиент не опознан | моды для одиночной игры, учебные проекты |
| `KNOWN_CLIENT_ACTIVITY` | проверенная идентификация объекта и след использования из других семейств (запуск, загрузка, удаление, переименование, агент JVM) | High при трёх семействах, иначе Medium | одиночная игра, тестирование, установка без использования на сервере |

Почему `RAN_THEN_DELETED` всегда Low, даже когда запуск подтверждён тремя источниками: подтверждён *факт*, но удаление использованной программы — обычное дело и не говорит о её назначении.

Почему два признака Защитника вместе не дают `CONCEALMENT_CLUSTER`: они из одного источника. Это видно на образе CI-машины: при сборке образа Защитнику добавили исключения и выключили защиту за одну секунду, а журналы очистили через 5 часов — находки нет, есть только две записи Low.

## Где проверено

| Что | Как |
| --- | --- |
| Связывание | одна ссылка MFT через переименование, неизвестный путь удалённой записи (серийный номер → буква), путь без ссылки; один путь у двух разных файлов — не смешиваются |
| Правила | каждое правило: срабатывает, не срабатывает без второго источника, не поднимается выше Low с одним семейством; Medium без двух семейств и High без идентификации отклоняет `Finding.Validate`; совпадение по названию не даёт идентификации; проверенный компонент с запуском и удалением — High |
| Объём | 200 000 записей за несколько секунд |
| Хранение | объекты и находки сохраняются и читаются со всеми полями; изменить или удалить их нельзя (триггеры) |
| Проверка целиком | корреляция прочитала все сохранённые записи, результат в той же базе, запись в журнале аудита |

## Чего ещё нет

- Связь по содержимому: SHA-1 из Amcache с файлами на диске (File Hunter считает только SHA-256), одинаковые копии в разных местах.
- Связь записей журналов событий о процессе с Prefetch по времени запуска (без ссылки MFT).
- Отчёт-хронология (этап 12); сейчас находки видны в CLI и в окне проверки.
